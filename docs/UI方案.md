# 酷狗播放器 —— UI 规划

> 版本：v0.1
> 日期：2026-11-02
> 状态：窗口已实现并跑通，本文件描述设计规格与登录方案

---

## 1. 设计目标

| 目标 | 具体含义 |
|------|----------|
| **为播放而生** | 不做社交、不做发现页瀑布流，所有结构围绕"找到歌 → 播起来" |
| **长开不累** | 深色为主，低饱和，避免大面积亮色和高频动效 |
| **会员状态一眼可见** | 哪些歌能播、哪些要登录，视觉上必须立刻可辨 |
| **登录不打断** | 登录是弹层 + 独立小窗，不跳转、不丢失当前浏览位置 |

设计基调：**克制的深色 + 单一强调色渐变**。参考 Spotify 的信息密度，但不模仿其暗色层次。

## 3. 登录设计 ⭐

这是本项目的核心环节——**没有登录，大部分歌都播不了**。

### 3.1 三种登录实现方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. 内嵌官方登录页** | Electron 开小窗加载酷狗官方登录页，用户正常扫码，登录后读 cookie | 无需逆向签名；支持扫码/短信/密码全部方式；官方流程变了也不受影响 | 多一个窗口 | ✅ **推荐** |
| B. 直连二维码接口 | 自己调 `login-user.kugou.com/v1/qrcode` 拿二维码 | 体验最原生，能完全自定义 | **实测返回 `20010 参数错误`，需要 signature**，逆向签名成本高且易失效 | ❌ 暂不采用 |
| C. 手动粘贴 Cookie | 用户从浏览器 F12 复制 | 实现最快 | 普通用户不会操作 | ⚠️ 仅作兜底 |

> 实测记录：`https://login-user.kugou.com/v1/qrcode` 无论怎么补 `appid` / `plat` / `qrcode_txt` 都返回 `{"data":"参数错误","error_code":20010}`，说明必须有签名。与其啃签名，不如直接用官方页面。

### 3.2 推荐流程（方案 A）

```
[主窗口] 点击「登录」
    │
    ▼
弹出登录遮罩（当前已实现）
    │  文案：打开酷狗音乐 App → 扫一扫
    ▼
点击「打开登录窗口」
    │
    ▼
新开 BrowserWindow 420×560（有边框、modal 父子关系）
加载 https://www.kugou.com/ 登录页
    │
    ▼
用户在官方页面完成扫码 / 短信 / 密码登录
    │
    ▼
监听 session 的 cookies 变化
    │  检测到 token / userid 出现
    ▼
关闭小窗 → 主窗口读取 cookie
    │
    ▼
用 safeStorage 加密写入本地
    │
    ▼
UI 切换到已登录态（头像 + 昵称 + VIP 标识）
    │
    ▼
trackercdn 请求带上 cookie，会员曲目返回直链
```

### 3.3 关键实现点

```js
// 1. 登录小窗
const loginWin = new BrowserWindow({
  width: 420, height: 560,
  parent: mainWindow, modal: true,
  webPreferences: { partition: 'persist:kugou' }   // 关键：独立持久化分区
})
loginWin.loadURL('https://www.kugou.com/')

// 2. 轮询 cookie，检测登录成功
const timer = setInterval(async () => {
  const cookies = await loginWin.webContents.session.cookies.get({ domain: '.kugou.com' })
  const token = cookies.find(c => c.name === 'token')
  const userid = cookies.find(c => c.name === 'userid')
  if (token && userid) {
    clearInterval(timer)
    saveSession({ token: token.value, userid: userid.value })
    loginWin.close()
  }
}, 1000)

// 3. 加密存储（Windows 下走 DPAPI）
const { safeStorage } = require('electron')
fs.writeFileSync(sessionFile,
  safeStorage.encryptString(JSON.stringify(session)))
```

**安全要求**：
- `partition: 'persist:kugou'` 让登录态与主窗口隔离，退出后可复用
- cookie 落盘必须过 `safeStorage`（Win 上即 DPAPI），**禁止明文写 JSON**
- 主进程持有 cookie，渲染进程只能通过 IPC 拿"是否已登录"和昵称，**拿不到 token 原文**

### 3.4 登录状态机

```
        未登录 ──点登录──> 登录中 ──成功──> 已登录(普通)
          ▲                  │                 │
          │                  │ 失败/超时        │ 检测到 VIP
          └──────────────────┘                 ▼
                                          已登录(VIP)
```

四种状态对 UI 的影响：

| 状态 | 曲目行 | 播放栏 | 右上角 |
|------|--------|--------|--------|
| 未登录 | VIP 曲目降透明度 66%，显示 VIP 徽章 | 点 VIP 曲目 → 弹登录 | 「登录」按钮 |
| 登录中 | 不变 | 不变 | 「登录中…」+ 脉冲点 |
| 已登录(普通) | VIP 曲目仍降透明 | 同上 | 头像 + 昵称 |
| 已登录(VIP) | **全部曲目正常显示** | 全部可播 | 头像 + 昵称 + VIP 金标 |

## 4. 视觉规范

### 4.1 色板

| 令牌 | 值 | 用途 |
|------|-----|------|
| `--bg` | `#0b0d12` | 主背景 |
| `--bg-elev` | `#11141b` | 标题栏 / 侧边栏 / 播放栏 |
| `--surface` | `#161a23` | 卡片、输入框 |
| `--surface-2` | `#1d2130` | hover |
| `--surface-3` | `#262c3d` | 进度条槽、滚动条 |
| `--border` | `#232838` | 分割线 |
| `--text` | `#e9ecf4` | 主文字 |
| `--text-2` | `#9aa3b8` | 次要文字 |
| `--text-3` | `#666e84` | 辅助文字 |
| `--accent` | `#2ca2f9` | 主强调（蓝） |
| `--accent-2` | `#7b6cff` | 渐变终点（紫） |
| `--vip` | `#f0b429` | VIP 金 |

> 强调色只出现在三个地方：播放按钮、选中态、进度条。**不要用在正文文字上**。

### 4.2 字体与数字

- 字体栈：`"Microsoft YaHei UI" → "PingFang SC" → system-ui`
- 字号：标题 24 / 正文 13 / 次要 12 / 辅助 11 / 徽章 9
- 所有**时间与序号用等宽数字**：`font-variant-numeric: tabular-nums`，否则秒数跳动时布局会抖

### 4.3 圆角与间距

| 元素 | 圆角 |
|------|------|
| 播放按钮 | 50%（圆形） |
| 封面 / 卡片 | 9px |
| 列表行 / 按钮 | 8px |
| 弹窗 | 16px |

间距基准 4px 栅格：4 / 8 / 12 / 16 / 20 / 26 / 30。

### 4.4 动效

- 时长：hover 130~160ms，弹窗 200ms
- 缓动：`cubic-bezier(.32,.72,0,1)`
- **进度条和音量只用 `width` 或 `transform`，不要触发重排**
- 禁止：旋转、弹跳、超过 300ms 的过渡

## 5. 交互规范

### 5.1 快捷键

| 键 | 行为 |
|----|------|
| `空格` | 播放 / 暂停（输入框内不生效） |
| `←` / `→` | 快退 / 快进 5 秒 |
| `↑` / `↓` | 音量 ±5%（**待实现**） |
| `Esc` | 关闭弹窗 |
| `Enter`（搜索框） | 立即搜索 |

### 5.2 鼠标

| 操作 | 行为 |
|------|------|
| 单击曲目行 | 选中（不播放） |
| **双击曲目行** | 立即播放 |
| 拖动进度条 | 实时 seek，松手生效 |
| 拖动音量条 | 实时调节 |
| hover 序号 | 序号 → 播放图标 |

### 5.3 必须补的三种态

| 态 | 现在 | 要补 |
|----|------|------|
| **加载态** | 无 | 列表骨架屏 + 播放按钮转圈 |
| **空态** | 无 | "没找到相关歌曲，换个关键词试试" |
| **错误态** | 无 | "网络异常" + 重试按钮；VIP 曲目 → "该曲目需要会员" + 去登录 |

## 8. 下一步建议

按依赖顺序，建议这样推进：

1. **先接真实搜索**（半天）—— 把 `MOCK` 换成 `/api/search`，验证数据链路
2. **再做登录**（1 天）—— 内嵌官方页 + cookie 抓取，这是播放 VIP 的前提
3. **然后接播放**（1 天）—— `<audio>` + 直链解析 + 过期重连
4. **最后补三态和打磨**（1 天）

第 2 步有一个**必须先验证的假设**：带着登录 cookie 请求，`trackercdn` 是否真的会给 VIP 曲目返回直链。如果这条路走不通，得改用 `wwwapi.kugou.com/yy/index.php?r=play/getdata` 那条带签名的路径。**建议第一步就先把这件事测了，再往下做 UI**。
