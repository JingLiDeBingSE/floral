## 二、按影响分层

### 1. 破坏手感的回归（必须改）

- **Esc 返回要 2 秒**（`g_exitT / 2.0`）。键盘动作 + 超长动画，双料违规，最该先改。
- **进播放页 2.2 秒**。点一首歌要等两秒多才看到完整信息；频繁切歌时动画永远播不完。
- **完全缺失按下反馈**。最便宜的体感提升，目前一个都没有。

### 2. 该砍 / 该减的

- 切歌 550ms 偏长，建议 360ms。
- 滚动拖影 5 层 ghost，建议 2 层 + 速度门控。

### 3. 性能

- 滚动时每帧绘制量 ×6（拖影）。和「切歌顿感」不是同一个问题（那个是音频预缓冲阻塞 UI，已修），但快速滚动会掉帧。

### 4. 可中断性与时序

- Toast 不可中断（时间到就消失），应改成淡出。
- hover 进出同速，应移入 150ms / 移出 100ms。

### 5. Origin / 一致性

- 面板 origin 全部正确：音质 / 音量 / 一起听锚在触发按钮，设置面板居中（模态豁免）✓
- 唱片转速注释与实现不符，一致性小问题。

### 6. 无障碍

- 完全没有 reduced-motion 支持。Windows 有系统级开关，读一次即可。

## 三、裁决：**Block**

理由：存在两条「破坏手感」的硬伤（Esc 2 秒、进页 2.2 秒），且缺少按下反馈这一基础项。

已完成的四项动效单独看**通过**：

| 项 | 结论 |
|---|---|
| 面板进出场（P0-1） | 通过 |
| 封面淡入（P0-2） | 通过 |
| 文字滑出/滑入（P1-5） | 通过 |

问题集中在**时间轴长度**（进/退/切歌偏慢）和**缺失项**（按下反馈、Toast、无障碍）。

## 五、审查用的判定标准（速查）

1. **是否该动**：一天上百次的操作不加动画；偶尔发生才加。
2. **目的**：反馈 / 空间一致 / 状态指示 / 防止跳变 / 解释 / 取悦（仅限首次）。
3. **曲线**：进入 `ease-out`，屏幕内移动 `ease-in-out`，hover `ease`，恒定运动 `linear`；UI 不用 `ease-in`。
4. **时长**：按钮 100–160ms，浮层 125–200ms，模态 200–500ms，UI 上限 300ms。
5. **物理正确**：不从 `scale(0)` 进场（用 0.95）；浮层锚在触发点，模态居中。
6. **只动 transform / opacity**。
7. **进出不对称**：用户决定的那一步慢，系统响应快。
8. **可中断**：高频触发的用过渡而非关键帧。
9. **无障碍**：reduced-motion 只减位移，不减淡变。
10. 不确定时，**删掉**往往是最好的动效决策。
