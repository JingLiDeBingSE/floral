# 歌曲列表（C++）

启动即显示封面网格，选一首歌进入播放页。无边框、圆角、莫兰迪粉配色。**有音频文件就真播，没有就退回模拟计时。**

Win32 + Direct2D + DirectWrite + DWM，音频用随源码附带的 miniaudio（`miniaudio.h`）。

## 播放

**默认边下边播，不写入磁盘**，避免消耗酷狗每月 300 首的下载额度。

打开一首歌时：
1. 先找数据目录下的 `audio/<hash>.flac` 或 `audio/<hash>.mp3`（想离线听可以手动放进去），有就播放本地文件
2. 没有就在后台线程解析播放地址，再由 `audio.cpp` 的下载线程把文件读进内存，解码器边下载边读取

解码器保留源文件的采样率，设备也按这个采样率打开，播放器本身不做重采样。设备采样率和系统的混音格式不一致时，由 Windows 转换。

下载跟不上播放时，音频回调输出静音，不等待网络。下载中途断开时，播放完已经收到的部分后显示“播放中断”，再按播放会从断开的位置继续。

### 音质档位

| 档位 | 酷狗 | 网易云 | QQ 音乐 |
|---|---|---|---|
| 标准 | `128` | `standard` | `128` |
| 高品 | `320` | `exhigh` | `320` |
| 无损 | `flac` | `lossless` | `best` |
| Hi-Res | `high` | `hires` | `best`（接口没有 Hi-Res） |

歌曲没有所选的档位时，三个平台的返回方式不同：酷狗返回 128k 的 MP3，所以按响应里的 `extName` 和 `bitRate` 判断实际档位，比请求的低时继续请求下一档；网易云返回不超过请求的最高档位，并在 `level` 里写明；QQ 的 `best` 依次尝试 FLAC、320k 和 128k，并在 `quality` 里写明。音质面板按实际拿到的档位标出这首歌可用的档位。

### 解析地址踩的两个坑

1. **`errcode 20028 / check r failed`** —— 设备校验。缺 `dfid`，服务端每次随机造一个假的，校验必挂。先 `GET /register/dev?mid=<随机>` 换真 `dfid`，再放进 cookie。
2. **`illegal hash or album_audio_id`** —— `album_audio_id` 必须传 **`mixsongid`**，不是 `audio_id`、也不是 `album_id`。

响应里 `url` 是**数组**，取第一个即可。

### 淡入淡出

主循环逐帧计算音量，通过 `AudioSetVolume` 交给音频回调：

| 情况 | 处理 |
|---|---|
| 手动切歌 | 旧曲用 0.25 秒淡出，音量归零后才切歌，避免爆音 |
| 从中途开始播放（换音质、一起听同步） | 用 0.45 秒淡入 |
| 从头开始播放、自动连播 | 不淡入淡出 |

自动连播以解码器读完整首歌为准（`AudioIsEnded`）。

### 进度条

跳转在后台线程执行。在线播放时要等下载追上目标位置，这段时间输出静音，界面显示加载动画；等待期间收到新的跳转请求时，当前的跳转提前结束，改为执行新的请求。

拖动时主循环暂停回读引擎位置，否则会被旧位置顶回去（就是"回弹"）。

## 播放页

左侧是一张转动的 CD，上下各有一个专辑盒子；右侧浮着歌曲信息。

```
 ▁▁▁▁▁▁▁▁▁▁  ← 上封套：和 CD 一样大，只露出 11% 高的一条
 ╭───────────╮
│     CD      │ ← 圆心离左边缘 10% 直径，露出约六成
 ╰───────────╯
 ▔▔▔▔▔▔▔▔▔▔  ← 下封套
```

- 唱片 `dd = min(W × 0.40, H × 0.62)`，`cx = dd × 0.10`、`cy = H × 0.50`
- 封套整块也是 `dd × dd`，但用 `PushAxisAlignedClip` 裁成 `dd × (dd × 0.11)` 的一条，贴在唱片上下
- 切歌时唱片飞到那条窄缝里缩小消失，新唱片再从另一条缝长出来
- 右侧信息栏 `px = max(W × 0.46, cx + dd/2 + 90)`

**切歌动画**（550ms，smoothstep）：

- 下一首：当前 CD 缩小飞入**上方**盒子，同时下一首的 CD 从**下方**盒子放大飞到中心
- 上一首：方向相反，当前 CD 飞入**下方**盒子

飞行途中两个盒子会暂时隐藏（`aTop/aBot` 归零），落定前 22% 再淡入 —— 否则盒子里的静态封面会和飞行中的唱片叠成双影。

**唱片的画法**：先由自定义的 Direct2D 效果（`vinyl.cpp`）用像素着色器画出黑胶部分，标签处留空；再用椭圆填充加位图画刷（`FillEllipse` + 带旋转的 `SetTransform`）把封面画成转动的圆形标签，最后画中心孔。标签的半径是唱片半径的 `LABEL` 倍。

- 光照按屏幕坐标计算，所以唱片转动时高光大致停在原处。沟槽的明暗纹理、灰尘和盘面轻微的起伏按唱片自身的角度计算，随唱片一起转，转动主要从高光里流动的纹理上看出来。起伏会让高光轻微摇摆、时明时暗。
- 曲间空隙、凸环和边缘这些结构只随半径变化，转到哪个角度都一样。比一个像素还细的细节按覆盖面积取平均或者淡出，所以小唱片上不会出现锯齿和摩尔纹。
- 着色器编译较慢，所以启动时注册效果之后，把着色器交给后台线程编译。第一次画唱片时如果编译还没有结束，会等它完成。编译或注册失败时，黑胶部分画成纯色圆。

全程不用 Layer，所以切歌动画期间也不掉帧。

## 网格布局

不是等宽方格，而是**不规则拼块**（类似 bento），列数随窗口宽度在 3 到 10 列之间变化：

| 权重 | 尺寸 |
|------|------|
| 73 | 1×1 |
| 12 | 2×1（横向长） |
| 12 | 1×2（纵向长） |
| 3 | 2×2 |

`TileLayout`（`tiles.cpp`）按阅读顺序逐格扫描，每遇到一个空格，就在放得下的尺寸里按权重选一个。选择由格子编号的哈希决定，同样的歌曲数和列数总是得到同样的布局。某个尺寸会在前面留下空格时，只有剩下的歌曲足够填满这些空格才允许选它，所以除了最后一行的末尾，网格里没有空洞。

## 悬停：周围的块让位

悬停某块时，它**在布局里真的占 2×2**，不是浮在上面盖住邻居。

`TileLayout::Expand` 先在覆盖光标所在格的几个 2×2 位置里挑一个：优先完整落在屏幕内的，其次与这块当前位置重叠最多的，再其次中心离光标最近的。然后以这个 2×2 区域为中心开一个窗口，完整落在窗口里的块可以挪动，也可以把宽或高缩成 1 格，压在窗口边上的块原地不动。窗口里用分支限界搜索把空出来的格子恰好填满，并让变化的块和移动的距离尽量少；搜索的节点数有上限，用完时采用已经找到的最好结果。窗口先向外扩 1 格，找不到解时逐步扩到 5 格；仍然找不到时，这块保持原来的大小，只显示悬停信息。

维护三份布局：

| 变量 | 用途 |
|------|------|
| `g_base` | 不含悬停的静止布局 |
| `g_target` | 悬停的块占 2×2，周围的块缩小或挪开 |
| `g_draw` | 每帧沿弹簧向 `g_target` 靠近 → 绘制用它 |

鼠标命中按 `g_target` 判定：先算出光标落在哪一格（格子之间的间隙两边各分一半），再查这一格在目标布局里属于哪块。放大后的 2×2 区域一定覆盖光标所在的格，所以块在移动途中，判定结果也不会来回跳。

## 性能

实测（1992 首、一屏约 20 个封面、150 张真封面）：

| 场景 | 优化前 | 现在 |
|------|--------|------|
| 空闲 | 5.4% | **0.0%** |
| 鼠标快速划过 | 26.5% | **4.7%** |
| 首次滚动（新封面） | 87.6% | **12.4%** |
| 再次滚动 | 16.1% | **22.6%**\* |

\* 第二次是继续往没封面（占位色块）的区域滚，绝对值仍是 3.6ms/帧。

### 四个真凶，按影响排序

**1. 滚动时现场解码封面（87.6%）**

滚到新封面时在 UI 线程上 WIC 解码，一张 2~4ms，一帧四五张直接把帧预算吃光。
→ 改为后台线程解码（`DecodeScaled`，缩到 320px 上限），主线程只做 `DrainDecoded()` 搬运。

**2. 每次 `WM_MOUSEMOVE` 都立刻重绘**

高回报率鼠标一秒能触发几百次全窗口重绘。
→ 改为只记 `g_mouseDirty`，每帧统一处理一次。

**3. 占位色块每帧重建渐变画刷**

1842 首没有封面，每块每帧要 `CreateGradientStopCollection` + `CreateLinearGradientBrush`，20 块就是 40 次 COM 对象创建。
→ 8 个色板画刷按渲染目标缓存，绘制时只改 `SetStartPoint/SetEndPoint`。

**4. 圆角用 Layer 裁剪（已单独修过）**

每块一个 `PushLayer`，强制分配离屏表面。
→ 改位图画刷 + `FillRoundedRectangle`。

### 顺带做的视口裁剪

按纵向每 220px 分条建立索引（`g_tgtBands`），绘制只遍历视口上下各一条范围内的块（约 20 个），不再每帧扫 1992 个；命中判定直接按格查表。

动画同理：只缓动视口内的块，视口外的直接到位。

### 提前建好位图

解码完成后，每帧最多预建 2 张 D2D 位图（`PrewarmCovers`）。每帧新建的封面位图总数也有上限（`COVER_UPLOADS_PER_FRAME`），一屏新封面会分到几帧里上传显存，滚动和进入歌单时都不会因为集中上传而卡顿。

## 动画

| 动画 | 实现 |
|------|------|
| 让位 | 每块的位置和尺寸沿临界阻尼弹簧追向目标（`SpringStep`），约 0.3 秒到位，中途换目标时速度保持连续；静止的块先画，移动中的块压在上面，悬停的块在最上层 |
| 平滑滚动 | 滚轮只改 `scrollTarget`，`scroll` 每帧追 22%，约 250ms 滑到位 |
| 运动模糊 | 滚动和歌单页拖动时，一起移动的内容先画到离屏图层，再经过自定义 Direct2D 效果沿移动方向取平均（`BeginMotionBlur` / `EndMotionBlur`）；拖影长度是这一帧移动距离的一半（`SHUTTER = 0.5`，即 180° 快门），最长 128 像素；内容停住约 30ms 后补画一帧不带模糊的画面 |
| 悬停信息 | 底部渐变压暗 + 白色曲名/歌手，圆角裁剪，任何封面上都能看清 |
| 页面切换 | `pageAnim` 缓动，网格层淡出缩到 0.95，播放层淡入从 0.95 放大 |
| 逐帧驱动 | 有动画时主循环每轮画一帧，`EndDraw` 等到垂直同步才返回，帧率跟随显示器刷新率；窗口在后台时按系统合成器的刷新时刻，每帧显示相同的整数次刷新，约每秒 60 帧；没有动画或窗口不可见时线程休眠，由计时器继续推进 `Animate()` |

运动模糊的像素着色器在启动时用系统自带的 `d3dcompiler_47.dll` 编译。编译或注册失败时，移动的内容照常绘制，只是没有模糊。

## 构建

```powershell
cd cpp
.\build.ps1                     # 编译 -> ..\build\songlist.exe
.\build.ps1 -Run                # 编译并启动
.\build.ps1 -Render shot.png    # 离屏渲染一张 PNG
```

直接编译：

```bash
g++ -std=c++17 -O2 -municode -mwindows -o ../build/songlist.exe \
    main.cpp data.cpp -ld2d1 -ldwrite -lwindowscodecs -lole32 -luuid -lshell32 -lgdi32 -ldwmapi
```

## 窗口

无边框（`WS_POPUP`），标题栏和最小化/最大化/关闭按钮全部自绘。

| 行为 | 实现 |
|------|------|
| 窗口圆角 | `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)` |
| 拖拽移动 | `WM_NCHITTEST` 标题栏返回 `HTCAPTION` |
| 边缘缩放 | `WM_NCHITTEST` 判断 6px 边框 |
| 去掉系统边框 | `WM_NCCALCSIZE` 返回 0 |
| 最大化不盖任务栏 | `WM_GETMINMAXINFO` 限制到工作区 |
