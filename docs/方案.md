# 酷狗代播放器（新 UI）方案

> 版本：v0.2 —— 纯播放版（已去掉歌词）
> 日期：2026-11-02
> 目标机器：Windows 11 (Build 26200) / 酷狗音乐 20.1.41.27870 / Node.js 已装

---

## 0. 结论速览

| 问题 | 结论 |
|------|------|
| 播放链路通不通？ | ✅ **已实测跑通**，能拿到 `audio/mpeg` 直链并流式播放 |
| 直链能不能直接给浏览器播？ | ✅ **能**。CDN 返回 `access-control-allow-origin: *`、支持 `Range`(206)、不校验 Referer、不校验 UA |
| 那还需要后端吗？ | ✅ **需要，但不是为了音频**。`mobileservice` 搜索接口**没有 CORS 头**，浏览器直连会被拦；且 Cookie 也不能暴露在前端 |
| 能播多少歌？ | ⚠️ **这是最大的限制**。实测 10 首里 3 首免费可直接播，7 首返回 `status:2`（VIP/版权受限）。海量曲库要播，必须用你自己的账号 |
| 要不要做歌词？ | ❌ 已按需求移除（krc 解密能力已验证可用，将来想加随时能加） |
| 推荐做法 | `Node 后端（只做 API 代理）+ 纯前端播放器`，音频走 CDN 直连，2 周内可出可用版本 |

**一句话方案**：后端只干一件事——替浏览器去调酷狗接口，把「歌名」换成「可播放的直链」；前端就是一个播放器，拿到直链直接丢给 `<audio>`。

## 1. 播放链路实测结果

这一节是本方案的全部依据，均为本机实际请求所得。

### 1.1 三步链路，全部走通

```
① 搜歌  mobileservice.kugou.com/api/v3/search/song   → 拿到 hash
② 换链  trackercdn.kugou.com/i/v2/?key=md5(hash+"kgcloudv2")  → 拿到直链
③ 播放  http://fsandroid.tx.kugou.com/.../xxx.mp3    → audio/mpeg，可 Range
```

第 ② 步的 `key` 计算方式：`md5(hash + "kgcloudv2")`，无需登录、无需签名。

### 1.2 直链的完整能力（实测响应）

```json
{
  "status": 1,
  "extName": "mp3",
  "fileSize": 7798507,
  "bitRate": 128000,
  "timeLength": 487,
  "fileName": "命运交响曲(古典音乐)",
  "url": [
    "http://fsandroid.tx.kugou.com/.../xxx.mp3",   // 镜像一
    "http://fsmobile.kugou.com/.../xxx.mp3"        // 镜像二（自动容灾用）
  ]
}
```

| 能力 | 实测结果 | 对方案的意义 |
|------|----------|--------------|
| `content-type` | `audio/mpeg` | 可直接播放 |
| `accept-ranges` | `bytes` | 拖动进度条可用 |
| `Range: bytes=0-2047` | **206** + 正确 `content-range` | 流式 seek 没问题 |
| `access-control-allow-origin` | **`*`** | **浏览器可直连，不需要音频代理** |
| Referer 校验 | 无 | 不用伪造来源 |
| UA 校验 | 无 | 换 UA 照样 206 |
| 多镜像 | 2 个 CDN 域名 | 一个挂了自动切下一个 |
| URL 时效 | 路径含请求时刻时间戳（如 `/202611021959/`） | **会过期，必须按需重新解析** |

### 1.3 关键分叉：免费 vs VIP

同一套请求，不同歌曲结果完全不同：

| 歌曲 | 结果 | 字段 |
|------|------|------|
| 命运交响曲（古典） | ✅ 可播 | `status:1` + `url[]` |
| I. Adagio sostenuto | ✅ 可播 | `status:1` + `url[]` |
| 春日心动日记（独立音乐） | ✅ 可播 | `status:1` + `url[]` |
| 晴天 - 周杰伦 | ❌ 受限 | `status:2` |
| 平凡之路 - 朴树 | ❌ 受限 | `status:2` |
| 成都 - 赵雷 | ❌ 受限 | `status:2` |
| 秋的思念 - 赵海洋 | ❌ 受限 | `status:2` |

**样本 10 首，可播 3 首。** 受限曲目返回 `status:2` + `trans_param.classmap.attr0`（版权/会员位图），`url` 字段直接不存在。

→ 这意味着：**不登录 = 只能当一个"免费曲目播放器"**。要播周杰伦这类曲目，必须带上你自己账号的 Cookie（若账号有会员则正常返回直链）。

> **边界声明**：本方案只使用「用户自己账号本来就有权播放的内容」，不实现任何绕过付费墙、破解会员限制的功能。受限曲目就是提示用户去官方客户端听。

### 1.4 还有一个坑：搜索接口没有 CORS

实测给 `Origin: http://localhost:5173`：

- 音频 CDN → `access-control-allow-origin: *` ✅
- 搜索接口 → **不返回任何 CORS 头** ❌

所以前端**不能**直接 `fetch` 酷狗接口，必须经后端转发。这也是整个架构存在的理由。

## 2. 架构

```
┌──────────────────────────────────────────────────────┐
│  前端：播放器 UI（React + Vite + Tailwind）            │
│  搜索框 / 结果列表 / 播放队列 / 播放控制 / 进度条       │
└──────────┬───────────────────────────────▲───────────┘
           │ ① 调本地 API                   │ ③ <audio src=直链>
           │   (localhost:7xxx)             │    CDN 允许 CORS *
┌──────────▼───────────────────────────────┴───────────┐
│  后端：API 代理（Node.js，约 300 行）                  │
│  ├─ /api/search   转发搜索，规避 CORS                  │
│  ├─ /api/resolve  计算 key，换直链，返回多镜像+时效     │
│  ├─ /api/playlist 登录态下的歌单/收藏（可选）           │
│  └─ Cookie 保管（只存后端，不落到前端）                 │
└──────────┬───────────────────────────────────────────┘
           │ ② 服务端请求（带 UA / Cookie）
┌──────────▼───────────────────────────────────────────┐
│  数据源：mobileservice（搜索） + trackercdn（换链）      │
└──────────────────────────────────────────────────────┘
```

**设计要点：音频不做代理。** 因为 CDN 已经给了 `ACAO: *` 和 Range 支持，直接让 `<audio>` 指向 CDN 最省事——不占后端内存、不耗带宽、拖动进度条天然顺滑。后端只负责"把 hash 换成地址"这件小事。

## 3. 核心链路设计

### 3.1 接口定义

```ts
// GET /api/search?q=晴天&page=1
{
  "tracks": [{
    "hash": "b3a52a7a958bf0aed0ebfba2e9a818b7",
    "title": "晴天",
    "artist": "周杰伦",
    "album": "叶惠美",
    "durationMs": 269000,
    "playable": false          // 由后端预判，UI 置灰"会员"角标
  }]
}

// GET /api/resolve/:hash
{
  "url": "http://fsandroid.tx.kugou.com/.../xxx.mp3",
  "mirrors": ["http://fsandroid...", "http://fsmobile..."],
  "format": "mp3",
  "bitRate": 128000,
  "fileSize": 7798507,
  "expiresAt": 1793621999
}

// 受限时
{ "error": "VIP_REQUIRED", "message": "该曲目需要会员账号" }
```

### 3.2 播放地址解析器

```
输入 hash
  ├─ 命中缓存且未过期？──是──> 直接返回
  └─ 否
      ├─ key = md5(hash + "kgcloudv2")
      ├─ 请求 trackercdn.kugou.com/i/v2/
      ├─ status === 1 ？ ──否──> 返回 VIP_REQUIRED（UI 提示）
      └─ 是
          ├─ 取 url[] 全部镜像
          ├─ 估算过期时间（URL 时间戳 + 2h）
          └─ 写缓存 → 返回
```

### 3.3 三个必须处理的细节

**① 直链过期 → 无缝续播**

URL 里的时间戳是"解析时刻"，一段时间后失效。播放长音频跨过失效点会中断。处理：

```ts
audio.addEventListener('error', async () => {
  const pos = audio.currentTime;
  const fresh = await fetch(`/api/resolve/${hash}?nocache=1`).then(r => r.json());
  audio.src = fresh.url;
  audio.currentTime = pos;   // 恢复原位置
  audio.play();
});
```

体验上用户几乎无感，只会有极短一瞬的停顿。

**② 多镜像容灾**

`url[]` 通常给 2 个域名，第一个失败自动切第二个，不必等超时。

**③ http 混合内容**

直链是 `http://`。如果 UI 从 `https://` 加载会被浏览器拦截。

- 本地开发：`http://localhost:5173` → 无问题
- 打包 Electron / WebView2 → 无问题
- 部署到公网 https → 需加音频代理（此时才需要 4.5 的代理）

→ 结论：本机自用**不需要**代理，保持简单。

### 3.4 状态管理

不用数据库也可以跑起来。建议：

- **播放队列** → `localStorage` 持久化（几百条足够）
- **搜索历史** → `localStorage`
- **直链缓存** → 内存 `Map`，带过期时间，进程退出即失效（直链本来就短命）
- 只有在做「收藏/歌单同步」时才需要 SQLite

## 4. UI 设计

### 4.1 页面骨架

只做播放，界面可以非常克制：

```
┌─────────────────────────────────────────────────┐
│  🔍 搜索框                    [设置] [登录状态]  │
├─────────────────────────────────────────────────┤
│                                                 │
│   ┌──────┐  歌曲标题                03:29  ▶   │
│   │ 封面 │  歌手 · 专辑                         │
│   └──────┘  [会员] 角标（受限时置灰）            │
│                                                 │
│   … 更多结果（虚拟滚动）                         │
│                                                 │
├─────────────────────────────────────────────────┤
│  ▶ ⏮ ⏭   ━━━━━●━━━━━━━  01:12 / 03:29   🔊 ⛶  │
└─────────────────────────────────────────────────┘
```

### 4.2 必要交互

| 功能 | 说明 |
|------|------|
| 搜索 | 输入防抖 300 ms，回车立即搜 |
| 双击播放 | 整行双击 = 加入队列并播放 |
| 队列 | 侧栏抽屉，支持拖拽排序、删除 |
| 快捷键 | `空格` 播放/暂停，`←/→` 快退快进 5s，`↑/↓` 音量 |
| 循环/随机 | 单曲循环、列表循环、随机三种 |
| 失效提示 | 受限曲目显示"会员"角标，点击提示去官方客户端 |

### 4.3 视觉

- 深色为主，封面主色提取做背景渐变（`canvas` 取色即可）
- 列表用 `transform` 做滚动，不要改 `top`
- 优先做「能长时间开着不刺眼」，别堆动效

## 5. 实施计划

| 阶段 | 内容 | 交付物 | 估时 | 验收标准 |
|------|------|--------|------|----------|
| **M0 打通** | 后端脚手架 + 搜索 + 换链 | `curl` 能拿到直链并用播放器打开 | 1~2 天 | 搜"命运交响曲"返回可用直链 |
| **M1 能听** | 播放器 UI + 队列 + 进度条 | 浏览器里能连续听歌 | 3~4 天 | 连播 10 首不中断，seek 正常 |
| **M2 好用** | 登录态 + 歌单/收藏 + 失效重连 | 能播自己歌单里的 VIP 曲目 | 3~4 天 | VIP 曲目直链正常返回 |
| **M3 成桌面应用** | Electron 打包 + 图标 + 全局快捷键 | 双击运行的 `.exe` | 2 天 | 干净机器可直接启动 |

合计 **9~12 天**（比 v0.1 少了一半，因为去掉了歌词和数据库）。

### 备选：跳过 M2

如果只想听免费曲目，**M0 + M1 三天就能出成品**，完全不需要碰登录。建议先这么干，确认 UI 满意后再决定要不要接账号。

## 6. 风险与边界

| 风险 | 影响 | 应对 |
|------|------|------|
| **VIP 曲目占比高** | 高——决定这东西好不好用 | 先做免费版验证；需要时接自己账号 |
| 接口非官方、随时变 | 中 | 全部收在 `kugou-adapter.js` 一个文件里，变了只改这 |
| 直链过期 | 低 | 3.3 的自动重解析 |
| 频繁请求被限 | 中 | 加缓存 + 请求间隔，别做批量爬取 |
| 版权 | 高 | **仅个人本地使用，不公开分发、不传播音频** |
| 法律 | 中 | 不破解 DRM、不绕付费墙、不解密本地数据库、不逆向客户端 |

**明确不做**：❌ 破解 `KGMusicV3.db`（已证不可行） ❌ 绕过会员付费 ❌ 分发音频 ❌ 歌词（本次范围外）
