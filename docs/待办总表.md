## 一、歌单选择界面（当前主线）

### 已完成的前置

- 开屏加载改成居中圆环，去掉 logo 和文字 ✅
- 加载环在进入开屏时 200ms 淡出交接 ✅

### 1. 拉全部歌单

**现状**：只拉「我喜欢」，接口 `/user/playlist` 已存在但只取第一个匹配项。

**方案**

- sidecar 增加「全量歌单」返回：`[{id, name, count, pic, is_def, source}]`
- 主程序在启动刷新时一并拉取，存 `playlists.tsv`
- 每个歌单封面（`pic`）按需下载，复用现有封面缓存目录

**预期**

- 启动多一次请求（约 300ms）
- 歌单数量 74 个（当前账号），需要支持分页
- 封面体积：74 张 × ~40KB ≈ 3MB

### 2. 圆形蜂窝排布

**方案**

- 每个歌单一个正圆（等大），外圈 1.5px 描边
- 列间错位：奇数列下移半格（Apple Watch 蜂窝），列间距 = 圆直径 × 0.92
- 拖动改变整体偏移，排列关系不变
- 圆形用 `FillEllipse` + 位图画刷（封面居中裁剪）

**预期**

- 74 个歌单 ≈ 视口外各留一屏，滚动时只画可见的（复用现有 `g_vis` 机制）
- 拖动跟手，松手带惯性衰减

### 3. 点击 → 居中 + 横向伸展

**方案**

- 点击时记录目标歌单，整体视角平移到把它放到窗口正中（350ms，ease-out）
- 其他圆被"挤开"：以选中圆为中心做一个径向推开位移（位移量随距离衰减）
- 选中圆本身横向展开成圆角矩形（高度不变，宽度从 d 到 ~3.2d），200ms
- 圆角矩形内显示：歌单名、曲目数、来源。超长省略号
- 再点一次进入歌单（进入动画待定）

**预期**

- 平移 + 变形同时进行，视觉上"这一张被拎起来摊开"
- 变形期间不做圆→矩形的路径形变，直接圆角半径从小变大（成本低、看不出）

### 4. 进入歌单

暂未设计。等 1~3 做完再定。

## 三、一起听

### 已完成

- 在场心跳（昵称显示）✅
- 时间基准改 UTC 毫秒 ✅
- 只在切歌/播停/拖进度/卡加载时同步（去掉 3s 心跳）✅

### 待做

**1. 跟随者拖进度同步**

现状：只有房主能影响进度；跟随者拖动只改自己。

方案：新增 `kind==6` 消息"我拖到了 X"，房主收到后执行 seek 并推状态广播。

预期：双向可控，但房主仍是权威（收到请求才执行）。

**2. 多人（2–6 人）**

用户已明确「先不干」。

方案概要：服务端 `peers` Map + 角色标记；`/state` 返回 `{host, peers[]}`；客户端只应用 host 的状态，面板显示成员列表；skip 去重。

工作量：约 150–200 行。

**3. skip 防抖**

现状：两端同时放不了会互发 skip，可能连跳两首。

方案：房主侧 1.5 秒内只接受一次 skip 请求。

**4. 房主离开提示**

现状：对方断开只提示"对方已断开"，没有"房主走了"的明确提示。
